# Contributing to the component library

## What this library is

- Electronic parts as data: every pin, rating and electrical number from the datasheet, each with its page cite.
- A short Python file per part of datasheet equations, and a generated Zener (`.zen`) file for the `pcb` circuit tool.
- Circuit blocks import these parts. A wrong number here reaches every design that uses it.

## Why a person checks the numbers

Worst-case analysis uses these numbers as limits, so a typo or misread table can pass a bad design. The review has one
goal: a person verifies where a machine cannot. The three classes (derived, human, reference) are defined once, in the
table at the top of the [README](README.md). Derived rows need no tick, no stamp and no agent record.

- Agents (verifier, adversarial reviewer) find defects before the PR. Their findings are applied or listed in the PR
  description as open items; nothing from them is committed and none of it counts as a check.

- A person opens the datasheet page and compares each number in the file with the image.
- Machine results do not count. A `verified` value written by a script or an AI (for example `sonnet-audit ...`) is
  a machine check, not a human one.
- Only a person runs `tools/stamp.py` (or `tools/review.py`), and only after checking the row. Agents never stamp.

## Setup

- Python 3.12 exactly (the CI version; equation hashes and stamps are valid only on it, other versions show `UNKNOWN` and
  refuse to stamp) with matplotlib, in a virtual environment: recipe in the README, "Python environment"
- poppler, for page images: `brew install poppler` (macOS) or `sudo apt-get install poppler-utils` (Debian/Ubuntu)
- pcb 0.4.x, the Zener toolchain (https://docs.pcb.new). This repo pins `pcb-version = "0.4"` in `pcb.toml`.
  Check with `pcb --version`.
- GitHub CLI, signed in: `brew install gh`, then `gh auth login`
- KiCad conversion tools only if a vendor file is Altium-only (see `docs/KICAD.md`).

```sh
git clone https://github.com/kb1lqc/AgentEDA-Parts.git
cd AgentEDA-Parts
python3 tools/verify.py --help
python3 -c "import matplotlib; print(matplotlib.__version__)"
```

Work on a branch, never on `main`: `git switch -c add/<Value>`.

## The two layers

| Layer | Files | Who edits it |
|---|---|---|
| Data and math | `component.toml`, `calc.py`, `catalog.csv` (MLCC series) | People and AI, checked against the datasheet |
| Circuit capture | `<Value>.zen`, `pcb.toml` | Nobody: generated by `python3 -m lib.zen` |

Do not put a datasheet number or equation in a `.zen` file. Change the TOML and regenerate.

## Add a component

Read `docs/spec/extract.md` for the defaults used for every judgement call. The full procedure is in CLAUDE.md.

1. **Check the part.** Note the datasheet revision, date, package and grade. If the datasheet covers several packages
   or grades and you do not know which one you need, ask the maintainer before going on.
2. **Put the files in place.** Both folders are git-ignored:
   - Datasheet PDF: `docs/datasheets/`
   - Vendor symbol, footprint and STEP: `docs/vendor/<Value>/`
   - Every other sheet a cite names (`DS p.<n> (<file>.pdf)`) goes in `docs/datasheets/` under that filename. One PDF
     can serve several parts.
   - Check each download is for this part and package. Altium-only files are converted per `docs/KICAD.md`.
3. **Make the part folder.** `--datasheet-url` is required; it is recorded, not fetched.

   ```sh
   python3 tools/scaffold.py <Mfr> <Value> --datasheet-url <https link to the PDF>
   ```

4. **Fill `component.toml`.** Every number gets min, typ, max, unit, conditions, scope and a `cite` naming the page.
   Format: `docs/SPEC.md` (index) and `docs/spec/`. Never copy a number from memory or from another part. A `note` is
   one or two sentences: the fact a reader needs to use the row. Longer reasoning goes in the Decision Log.
5. **Write `calc.py`.** One function per datasheet equation, each citing its page. Format: `docs/spec/lib-api.md`. Equation
   records (`equations.toml`, find before writing, human stamp): `docs/spec/equations.md`, `python3 tools/equations.py`.
6. **Fix the symbol and footprint.** Rules: `docs/KICAD.md`.
7. **Generate.** Do not edit these by hand.

   ```sh
   python3 -m lib.zen
   python3 -m lib.readme
   ```

   `lib.readme` also refreshes `docs/PARTS.md` (the parts index), `docs/EQUATIONS.md` (the equations index) and the count at the top of `README.md`.
8. **Run the gate.**

   ```sh
   python3 tools/verify.py                  # the folders you changed; prints PASS or the first 5 failures
   python3 tools/verify.py --regen          # only when the generated files are meant to change
   ```

   With no folder names it checks the parts you changed; with no changes it stops with `nothing was built`. If it
   reports a stale `review/review.toml`, run it with `--regen` and commit the updated file. CI fails a PR whose
   `review/review.toml` is stale.
   For a catalog series (MLCC), also run the export check with the manufacturer export in `docs/datasheets/`:
   `python3 -m lib.catalog export-check <export.csv> components/<Mfr>/<Value>`. On MATCH it writes
   `review/export_check.toml`; commit it. Derived rows then need no tick. When the export is refreshed, regenerate the
   committed subset (`python3 -m lib.catalog export-subset <export.csv>`, writes `docs/exports/`) and every record.
9. **Open a pull request** with `gh pr create`. This PR holds the part, its generated files and the export record, with
   no human stamps. The human check comes next, in its own PR (below). CI runs `tools/verify.py --all`. Rows still awaiting a human check do
   not fail CI. A bot comment on the PR shows `<k> of <n> rows that matter checked` for each part the PR changes.

### Part types

| Type | When | Example |
|---|---|---|
| Single part | One orderable | `TexasInstruments/TPS48000QDGXQ1` |
| Family (`variants.toml`) | Same package, different grade or option | `AnalogDevices/LTC4364MS`, `TexasInstruments/INA241DGK` |
| Value series | The datasheet prints the part-number rule and a regular value set | `Panasonic/ERJ-3EKF`, `Panasonic/ERA-3AEB` |
| Value series with tolerance options | Several tolerances, each with its own range | `Vishay/WSK2512` |
| Catalog series | Irregular availability; values from a manufacturer export, cross-checked by decoding each part number | `Murata/GCM188` |

## Verify parameters (the human check)

Run this in your own terminal, not an agent's, from the repo root, with the PDFs in `docs/datasheets/` and poppler
installed (see Setup). A person ticks each row; no agent runs this tool. Do the check on a `review/<part>-<login>-<date>`
branch whose PR contains only stamps (`verified` lines, the part's `review/` and README); fixes to numbers, code or docs
go in a separate PR.

```sh
python3 tools/review.py INA229AIDGS                     # one part (its folder name under components/<Mfr>/)
python3 tools/review.py INA229AIDGS TPS48000QDGXQ1      # several parts
python3 tools/review.py                                 # every part
python3 tools/review.py --list-blocks                   # the circuit blocks you can review
python3 tools/review.py --block INA229HighSideMonitor   # only the rows that block reads
python3 tools/review.py INA229AIDGS --dry-run           # try the page; shows the commands the button would run, runs none
```

### Circuit blocks

`--list-blocks` and `--block` read a blocks repo (for example AgentEDA-Blocks, or your own), not this one. Point them at your checkout with
`--blocks-repo <path>` or the `CIRCUIT_BLOCKS` environment variable (the same variable `tools/risk_rank.py` reads).
There is no default folder: without either, the tool refuses and says so.

- A block is listed only after its `analysis.py` has written
  `benches/<Block>/docs/design-analysis/library-inputs.json` in that repo. Run the block's analysis first.
- `--block` narrows the page to the rows that block reads. It never changes a part's status.

The page opens in your browser. It starts with one status line per part, then shows the rows that matter, grouped
into Limits, Used by equations, and Pins & package. Each row has its statement, the datasheet crops, and one tick box.
Rows with no tick box say why (usually `Fix first`, or missing evidence; run `python3 tools/verify.py <folder>`).
Full rules: `docs/spec/review-view.md` and `docs/spec/review.md`.

### Three outcomes

- **Matches:** tick it.
- **Wrong:** leave it unticked. Fix the TOML with the correct number and cite, run `tools/verify.py --regen`, and
  commit `review/review.toml` too. Never stamp a wrong row.
- **Unclear:** leave it unticked and open an issue. `.review-cache/<Mfr>/<Value>/github-issue.md` has the text.

### What to compare

- value and sign (a minus sign matters)
- unit
- min, typ and max, in the right column (read the table header image)
- conditions: temperature, voltage, load, package
- footnotes that change the value
- the cite: right table, right page, right row

### Press Stamp

Compare, tick, then press **Stamp N rows and open PR**. The tool needs a clean working tree (untracked files are
fine). It makes a branch `review/<parts>-<login>-<date>` from `origin/main`, runs `tools/stamp.py` on the ticked
rows, regenerates the affected parts, commits, pushes and opens the PR. If `stamp.py` refuses, it returns to your
branch and deletes the new one. If `verify` fails, it stops and leaves the changes uncommitted for you. `--dry-run`
shows the commands and runs none.

Each stamped row gets one line bound to the datasheet file and the row's numbers:

```toml
verified   = "human:<github-login> <YYYY-MM-DD> page-image ds_review <pdf-sha256 first 12> row <row-hash first 12>"
```

The pinout has its own line under `[pinout]`. If the row, a pin or the PDF changes later, the stamp stops matching
and the row needs a check again. CI (`tools/check_stamps.py`) fails a PR whose new human stamp names anyone other
than the PR author.

Fallback, by hand: `python3 tools/stamp.py <Value>:<key>`, then `python3 tools/verify.py --regen <folder>`. Stamp
refusals and their fixes are listed in `docs/spec/review.md`.

## Release

`.github/workflows/release.yml` is a manual run from `main` (Actions, "release"). It runs the full gate, asks
`pcb publish --check` which component tags the current `main` needs, and creates exactly those. An optional library
tag `vX.Y.Z` is added when you give a version. The run is a **dry run by default**: it shows the plan in the run
summary and pushes nothing. Turn off `dry_run` only when the plan is right.

## Glossary

| Term | Meaning |
|---|---|
| rows that matter | Rows a person must tick: absolute maximums, package dimension and land rows (not assembly-test, mass or weight rows), junction-to-case and maximum junction temperature, every value a calculation uses (including a catalog series' temperature-coefficient rows), and the pinout. Rule: `docs/spec/review-view.md`. |
| derived | A value a script proves on every verify (catalog rows against the manufacturer export). Needs no tick. |
| used value not covered | A value the library uses that the review record does not cover yet (a catalog or variant key). It is not counted in k or n. |
| stamp (verified line) | The `verified = "human:<login> ..."` line a person writes after ticking a row against the page image. |
| checked, needs check, reference | Row states on the review page. |
| scope `25C`, `partial`, `full`, `na` | Temperature scope: 25 °C only; part of the grade's range; the full range; `na` = not temperature-scoped (abs max, mechanical, or a single stated temperature). |
| `check_pins`, `check_ambient` | Which pins, or the board ambient, the generated Zener wrapper checks against the row. |
| `owner: module / board / assembly` | Who must check a row the wrapper does not check. |
| UNVERIFIED | Wrapper result: a checked net has no declared voltage range. |
| waivable | A `25C` or `partial` row: a warning the designer may waive with a cited reason, not an error. |
