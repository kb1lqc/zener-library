# Extraction spec: component.toml, calc.py, units, defaults

Loaded by the extractor and verifier. Format contract: humans verify it against the datasheet (DS) with the PDF open.
Datasheet tables are read as rendered page images, never as extracted text (it scrambles columns).

Terms: **MPN** = exact orderable number with reel suffix (LTC4364HMS-1#TRPBF). **Value** = MPN without the reel
suffix (LTC4364HMS-1); it names the directory, or a variant in a family's `variants.toml`. **Cite** = `DS p.<printed page>, <table or figure title>, <row>`
(printed page numbers; pages with no printed number: `DS PDF p.<n>, <drawing number>`). A row from a document other than
`datasheet_file` (a second reference sheet, an errata) must name it by file name in brackets after the page (naming
`datasheet_file` itself is allowed):
`DS p.7 (GCM1885C1H101GA16-01A-EN.pdf), Table A, 5C, -10 degC`; `lib.check` confirms the file is in `docs/datasheets/`.

## Rules that override convenience
1. **Every number has a cite.** `DS p.<printed page>, <table or figure title>, <row>`. No cite, no number.
2. **Never invent a value.** If the datasheet gives only typ, store only typ. If it gives only max, store only max.
   Do not fill a missing min/typ/max with a guess, a midpoint, or a value read off a curve. A value the datasheet does not print (including a part-number code) is excluded and logged. Curve readings are allowed
   only in a separate field `curve = true` and are never used as worst-case bounds.
3. **Store raw datasheet values in the datasheet's printed units.** No derating, no rounding, no unit conversion
   in the TOML (one exception: a quantity printed per N pieces, see Units). The loader converts to SI.
4. **Simple beats clever.** Plain Python, plain TOML, standard KiCad files. Python stdlib + matplotlib only.
5. **The newest-format reference sheet wins** when sheets in one series conflict; log the older values.

## Directory layout

```
components/<Manufacturer>/<Value>/     Value = orderable part minus reel suffix (INA821IDGK)
  component.toml        part info, pins, parameters (the data)
  calc.py               datasheet equations as plain functions (the math)
  <Value>.kicad_sym     KiCad symbol      (fixed up from vendor, see docs/KICAD.md)
  <Value>.kicad_mod     KiCad footprint   (pads per datasheet land pattern; STEP embedded when available)
  README.md             GENERATED by `python3 -m lib.readme`; never hand-edit
lib/                    loader, units, worst-case engine, report/plot helpers, validator
examples/               worked circuit analyses that use several parts
docs/datasheets/        PDFs (not committed)
docs/vendor/<Value>/    vendor KiCad/STEP downloads (not committed)
```

### Fields

| Field | Required | Meaning |
|---|---|---|
| `name` | yes | Plain-English parameter name |
| `symbol` | if DS has one | Symbol exactly as printed |
| `kind` | yes | `abs_max`, `rec_op`, `electrical`, `thermal`, `mechanical` |
| `scope` | yes | `25C` = only at 25 °C (also a row that inherits a "TA = 25 °C" table header and has no temperature condition of its own); `full` = over the grade's full temperature range; `partial` = over only part of the grade's range (say which in `conditions`; the note names the row to use instead; do not use for worst case over the full range); also used, with a note saying why, for a rec-op row that applies only under a condition the independent-net check cannot see (a feature in use, a pin wired a certain way, two pins on the same net), so its Zener check is a waivable warning; `na` = anything else (abs max, mechanical, or a single stated temperature such as "at 70 °C", which then goes in `conditions`) |
| `min` / `typ` / `max` | one of these or `text` | Numbers exactly as printed. A `±X` limit is `min = -X, max = X` |
| `text` | if no number | A rating the DS states in words or as a formula ("Continuous", "(P x R)^1/2"). Use only when there is no number |
| `unit` | yes | See units. Use `""` for unitless (gain V/V, ratio) |
| `conditions` | yes | Test conditions as printed; `""` if none |
| `cite` | yes | `DS p.<printed page>, <table/figure title>, <row>`; from another document: `DS p.<n> (<file>.pdf), ...` |
| `min_ref` / `max_ref` | no | Name of a pin or rail the min/max is relative to. Example: VCM range `(V-)+2 V to (V+)-2 V` is `min = 2, min_ref = "-VS", max = -2, max_ref = "+VS"` |
| `typ_ref` | no | Like `min_ref`/`max_ref`, for typ: the DS prints "Typ = VS + 11 V" as `typ = 11, typ_ref = "+VS"`. `part.resolve()` returns typ = offset + the rail's typ (a float rail is exact; a rail Param without typ gives typ `None`). The Zener generator ignores typ |
| `tol_pct` | no | `[lo, hi]` printed percentages: the DS prints a typ with "-10 % / +10 %" in the MIN/MAX columns. Store `typ` as printed plus `tol_pct = [-10, 10]`, no `min`/`max`. The loader sets min = typ x (1 + lo/100) and max = typ x (1 + hi/100), sorted so min <= max (also for a negative typ); wca and Zener checks use those. The README shows "-10 %" / "+10 %" in the Min/Max cells |
| `variants` | no | Family directories only: list of variant Values the row applies to; absent = all variants (see "Families and variants") |
| `dielectric` | no | Capacitor series only: the row applies to catalog parts of that dielectric (`"X7R"`); absent = all (see "Capacitor series") |
| `parts` | no | Capacitor series only: list of catalog values (MPN without package letter) the row applies to; absent = all. A row has `dielectric` or `parts`, not both |
| `note` | no | Footnotes, characterization notes, ambiguity |
| `verified` | no | `"<who> <YYYY-MM-DD> <method>"`: an independent check of this row after extraction. Pair with `verification_type` for explicit provenance. Never set by the extractor of the row. A judged PASS resting on a row without it reports `PASS (UNVERIFIED INPUTS)` (`lib-api.md`) |
| `verification_type` | no | `human_page_image`, `cross_model_page_image`, or `manufacturer_export`; must accompany `verified`. Legacy `verified` stamps without this field remain usable but are not counted as human-reviewed. Text-layer checks are never a verification type |
| `sym` | no | `true` if the DS prints an unsigned magnitude bound for a quantity that can have either sign (VOS, IB, IOS, offset drift: TI prints VOS "40 uV" max, meaning ±40 uV). Store `max` (and `typ`) as printed; the loader sets min = -max. Say why in `note`. Never for a quantity that cannot be negative (IQ), and never for a printed `±X` (that is `min = -X, max = X`) |
| `check_pins` | no | Zener wrapper: list of `[[pin]]` names whose net voltage must stay within this row's min/max (with `min_ref`/`max_ref` resolved to those pins' nets). Voltage rows only. See "Zener wrapper" |
| `check_ambient` | no | Zener wrapper: `true` checks the instance's `ambient` config against this row (degC, min and max required) |
| `unchecked` | no | Reason a rating row is not a Zener check, or why some of its pins are not (`owner: module`, `covered by <key>`). Every `abs_max` and `rec_op` row needs `check_pins`, `check_ambient` or `unchecked` |
| `typ_pm` | no | `true` if the DS prints `±X` in the TYP column; see "Signs and ordering" |
| `curve` | no | `true` if read off a graph. Must name the figure or graph in `cite`. Never a guaranteed bound: a calc function that uses one must say in its docstring that the result is a curve-based estimate |


Signs and ordering:
- Always store `min <= typ <= max` numerically. Some datasheets print negative currents in magnitude order
  (MIN -2, MAX -6): store `min = -6, max = -2` (printed MAX -> `min`, printed MIN -> `max`) and say so in `note`,
  quoting the printed columns.
- A printed `±X` limit is `min = -X, max = X`.
- A printed `±X` in the TYP column (gain error typ ±0.025 %) is a spread around zero: store `typ = X` and
  `typ_pm = true`. The loader returns typ = 0 and keeps X as `typ_spread`. Do not use `typ_pm` where ± means two
  directions of a magnitude (short-circuit current ±20 mA source/sink): store the magnitude and explain in `note`.
- A dual-supply range printed `±2.25 V to ±18 V` is stored as the magnitude per rail, with a note.
- Negative quantities stay signed (sourcing currents printed negative stay negative). A calc function that needs a
  magnitude takes `abs()` of its argument and says so in its docstring.
- A rating with no stated reference pin (INA821 supply ±20 V): store as printed and say in `note` how it is applied
  (each pin relative to the part's ground/common; if the DS also states it as a span, "40 V (±20 V)", it is covered by the rec-op span row). If the DS states the reference anywhere ("all voltages referenced
  to GND"), cite it and set `min_ref`/`max_ref` to that pin name. Pin-pair rows (VGS, SENSE-OUT) use the second pin as ref.
- A rating printed with no MIN/TYP/MAX label (power, current, voltage max) is `max`.
- A rating stated in words or as a formula ("Continuous", "(P x R)^1/2") is a `text` field with no numbers.

If one parameter has rows for 25 °C and full temperature, make two keys: `vosi_25c` and `vosi_full`.

### Units

Write the unit as printed, using ASCII. Per-part values (the one unit conversion allowed in the TOML): a datasheet that prints "63.6 g / 1000 pieces" is stored as
the per-part value in a unit that keeps the printed digits (63.6 mg) with the printed wording in `conditions`. A unit is `[prefix]base[suffix]` with prefix `f p n u m k M G`, base
`V A ohm W F H Hz s C J` (C = coulomb for gate charge, J = joule for avalanche energy), and optional suffix `pp` (peak-to-peak), `/rtHz`, `/degC`, `/us`, `/MHz`, `/V` (transconductance). Examples: `V mV uV nV A mA uA nA pA ohm mohm kohm Mohm W mW F uF nF pF H uH Hz kHz
MHz s ms us ns uVpp nV/rtHz fA/rtHz uV/degC V/us uA/MHz mA/V us/V`. Converted: `mm` -> m, `g mg` -> kg, `uV/V mV/V m%` -> fraction, `mdegC` -> degC, `kcycles` -> cycles (10 kcycles -> 10000), `%` -> fraction
(0.5 % -> 0.005, unit `1`), `ppm` -> fraction (35 ppm -> 35e-6, unit `1`), `ppm/degC` -> 1/degC (unit `1/degC`), `ppm/V` -> 1/V (unit `1/V`). `/us` -> `/s` (2.5 V/us -> 2.5e6 V/s). `/MHz` -> `/Hz` (23.4 uA/MHz -> 2.34e-11 A/Hz). `uV/V` and `mV/V` stay fractions, never `/V` transconductance.
Unscaled: `degC degC/W dB bits LSB cycles years` and `""`. So every value a calc function receives is SI or a plain fraction; README
tables still show the printed units. The loader rejects any unit it does not know.

### Pin types (KiCad)
`input output bidirectional tri_state passive free unspecified power_in power_out open_collector open_emitter no_connect`.
Choose from the datasheet's pin function text, not from the vendor symbol. Pins for external components (gain resistor,
compensation) are `passive`. Exposed pads appear as a pin when the datasheet says to connect them.

## Defaults instead of questions

Apply the default, add a Decision Log row, add the open item, continue. Rows already stated above (Fields, Signs
and ordering, Units) are not repeated here.

| Case | Default |
|---|---|
| "Specified by characterization" | Store as guaranteed; note "characterized, not production tested (DS note N)" |
| DS contradicts itself | Priority: pin function text > pin diagram > I/O column; table > feature bullets. Record as open item. **Stop** if pin number, position or count disagree between diagram and table |
| NC / DNC / exposed pad | DS wording, quoted in the pin `function`. Exposed pad that must connect to X: a pin sharing X's name. Wording missing: **Stop** |
| No Absolute Maximum Ratings table (passives) | Map the DS's own rating tables to `rec_op` / `electrical` honestly; say so in a TOML comment |
| Range-dependent rows (resistor value ranges) | Use only the row covering this Value; name the row in `cite` |
| Land-pattern dimensions labelled only by letter | Neutral name ("Land pattern dimension c (DS p.2 diagram)"); inferred meaning in note, marked inferred; unconfirmed ones are open items |
| Alternates | Only the same part in other packaging (reel/tube). Other grades, tolerances or second sources: open item |

### Check-row defaults (Zener wrapper)

Every `abs_max` and `rec_op` row gets exactly one disposition: `check_pins` (voltages the circuit sets: supplies,
signal inputs, pull-up rails, divider inputs, REF; names exactly as in `[[pin]]`), `check_ambient` (the grade's
temperature range) or `unchecked` with a reason. A limit relative to another pin takes `check_pins` plus
`min_ref` / `max_ref` = that pin's name. A rec-op-like Electrical Characteristics row (VCC operating range) may also
get `check_pins`; it becomes an error.

| Case | Default |
|---|---|
| Rating row on a pin the part drives (amplifier or regulator OUT, gate drive, TMR, COMP, SS) or whose voltage external parts set (MOSFET SOURCE, SW). A load or bus node the part only senses (hot-swap OUT, SENSE) is circuit-set: check it | `unchecked = "<reason>; owner: module"` |
| Abs-max row looser than a checked rec-op row on the same quantity (TA abs vs grade, supply abs vs rec-op span) | `unchecked = "covered by <key>"` on the looser row; check the stricter one |
| Abs-max row with no reference pin, part has no ground pin (amplifiers) | `check_pins` with no ref: checked against system 0 V; note says so |
| One abs-max row covers several pins, some part-driven (FB, TMR) | `check_pins` on the circuit-set pins, `unchecked` names the rest and why |
| Supply span printed as single and dual ranges | Check the span once (`check_pins = ["+VS"]`, refs `-VS`); the other row `unchecked = "same span as <key>"` |
| Storage, lead/solder temperature, ESD | `unchecked = "owner: assembly"` |

Revision currency, errata, PCN and lifecycle are not checkable (no web access): log them as open items ("not checked"), never ask.
A vendor symbol older than the KiCad 10 format is handled in docs/KICAD.md.

## calc.py

Datasheet equations, one function per equation. Rules:

- Arguments and return values are plain floats in SI units (V, A, ohm, W, s, Hz), temperatures in °C.
- The docstring states: the equation as text, the cite, and units of every argument and the return value.
- No access to the TOML. Parameters are passed in as arguments so the worst-case engine can sweep them.
- `INPUTS` maps each function's arguments to the `component.toml` param key that supplies them, so nobody has to
  guess which of 80 rows to use. Arguments that are design choices (resistor values, load current) are not listed.
  A value is `"key"` (pass the whole Param; wca sweeps its min/max) or `"key.min"`, `"key.typ"`, `"key.max"`
  (pass that one number, e.g. `"p70.max"` for a rating, `"vcc_op.min"` for a minimum supply). `part.inputs("fn")`
  returns the arguments.
- A `sym = true` row with a printed typ is centred like `typ_pm`: typ = 0, printed typ kept as `typ_spread`.
- Equations not printed in the datasheet but needed to use it correctly (a pin bias current through a divider's
  Thevenin resistance) are allowed only if the docstring starts with `Not a DS equation:` and gives the derivation. An optional
  argument that extends a DS equation (default reproduces the DS equation exactly) may instead carry a line
  `With <arg> != 0 this is Not a DS equation: ...` with the derivation.
- A value stored as typ only is never a bound; INPUTS maps it as `key.typ`. Functions that fit a typical curve end in `_typ`, their docstring names the guaranteed rows, and they must not be used as worst-case bounds.
- `EXAMPLES` lists datasheet worked examples or table values that the function must reproduce. Prefer numbers the datasheet itself prints (gain table, design example).

```python
def gain(rg):
    """G = 1 + 49.4 kohm / RG.  DS p.20, 8.3.1 Gain-Setting, Equation 1.
    rg: gain resistor, ohm.  Returns: gain, V/V."""
    return 1 + 49.4e3 / rg

EXAMPLES = [
    # (function, kwargs, expected, tolerance, cite)
    # tolerance is relative (1e-3 = 0.1 %), except when expected == 0, where it is absolute.
    ("gain", {"rg": 5.49e3}, 9.998, 1e-3, "DS p.20, Table 8-1, G = 10 row"),
]

INPUTS = {
    # function: {argument: param key}
    "vos_rti": {"vosi": "vosi_full", "voso": "vos_o_full"},
}
```

## Temperature and combined errors (the one recipe)
1. If the DS has a full-temperature row (`scope = "full"`), use it: it already covers the whole grade range.
2. Otherwise use the 25 °C row plus drift: `X(T) = X25 + drift * (T - 25)`, with `T` an explicit wca input
   (`Param(min=-40, max=125)`) and `drift` the drift param. Never extrapolate a typ-only drift as a bound.
3. Independent error terms (tolerance, TCR x dT, aging test limit) are separate wca inputs to one function, e.g.
   `R = R0 * (1 + tol) * (1 + tcr * (T - 25))`. Corners then combine them worst case. Each part's `calc.py` should
   provide such a combined function for its main quantity.
