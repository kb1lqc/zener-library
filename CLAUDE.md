# Component library: orchestrator rules

Datasheet numbers, equations and KiCad files for nominal and worst-case analysis. No boards. I review every diff. Correctness beats speed. Never guess a number. Simple beats
clever: plain TOML, plain Python (stdlib + matplotlib), standard KiCad files. Generic role split: `agent-roles` skill.

## Two layers, one source of truth
- `component.toml` + `calc.py` (+ `catalog.csv`) hold every datasheet number and equation, each with a cite; humans
  verify them against the PDF; all analysis runs in Python (`lib/`).
- `<Value>.zen` + empty `pcb.toml` are GENERATED by `python3 -m lib.zen`. Never put a datasheet number or equation
  in Zener; change the TOML and regenerate. A number lives in one place.

## Where things live
Format contract: `docs/SPEC.md` index, files in `docs/spec/`. KiCad rules: `docs/KICAD.md`. Equation records and stamps: `docs/spec/equations.md`, `tools/equations.py`. Briefs: `docs/briefs/`.
Reference packages: `components/TexasInstruments/INA821IDGK/` (amplifier), `.../AnalogDevices/LTC4364MS/`
(family), `.../Vishay/WSK2512R0250D/` (passive). `docs/notes/`: humans only.
Generated, never hand-edited: `components/**/README.md`, `<Value>.zen`, `docs/PARTS.md` (the parts index; the root
README holds only a count and a link), `docs/EQUATIONS.md` (the equations index) and the block between the `review-status` markers in `README.md`, all by
`python3 -m lib.readme` (run by `verify`). A new part appears in `docs/PARTS.md` by regenerating, never by editing.
"Is this part safe to use?": `python3 tools/status.py <Value> [--json]` (ledger only, no PDFs or export). A blocks repo
(AgentEDA-Blocks or any other) uses the library as in `docs/spec/blocks.md`. No worked examples live here: they belong
in a blocks repo.

## Ground truth, toolchain
- Reads outside the repo are blocked. Datasheets: `docs/datasheets/`; vendor files: `docs/vendor/<Value>/`.
- No web, no `pcb auth`: revision, errata, PCN, lifecycle are open items "not checked", never questions.
- Read datasheet tables as page images, never extracted text.
- Work on a branch; touch only needed files; no commit unless I ask.
- pcb 0.4.x. The shim self-updates; `pcb +0.4.101 <cmd>` pins a version.
- After every change, from the repo root: `python3 tools/verify.py` (builds the changed component dirs; `--all`, or
  list dirs; `--regen` when a generator change is intended). It runs `lib.check`, `lib.zen`, `lib.readme`,
  `tools/ds_review.py`, `pcb build -Wstyle -Dwarnings`, unittest by exit code, fails closed, prints one PASS line or the
  first 5 failures plus a log path. Tolerated (counted): `datasheet_file not found`, `datasheet_url empty`. New part
  dir: `python3 tools/scaffold.py <Mfr> <Value> --datasheet-url <url>`. A hook formats `.zen`, checks edited parts.

## Component procedure (one Value per directory)
0. **Pre-flight.** Datasheet, datasheet URL (scaffold `--datasheet-url`), vendor files (symbol, footprint, STEP),
   `pdftoppm`, python3 3.11+ with matplotlib. Missing items I must supply: ONE message listing all with exact paths;
   continue without them, except a missing datasheet: stop. STEP missing: `step = "none"`, open item.
1. **Intake.** Revision, date, MPN decode, lifecycle as printed. Several packages, grades or options and none named:
   Stop. Same-package orderables: family dir (`docs/spec/family.md`); MLCC: `docs/spec/capacitor.md`; resistor
   series: `docs/spec/series.md`.
2. **KiCad files** (`docs/KICAD.md`); check the footprint vs the DS land pattern.
3. **Extract** `component.toml` and `calc.py`: extractor brief. Defaults table in `docs/spec/extract.md`.
4. **Zener wrapper**: wrapper brief and `zener-wrapper` skill.
5. **Verify**: verifier and adversarial reviewer in parallel. Apply findings that cite the DS or the spec; log the
   rest as open items. A format change: spec first, then data, then `lib/` with tests. One targeted re-review.
6. **Generate** `python3 -m lib.readme`; re-run examples that use it. Catalog series (MLCC): with the manufacturer
   export in `docs/datasheets/`, run `python3 -m lib.catalog export-check <export.csv> <dir>` and commit
   `review/export_check.toml` (derived rows: a script proves them, no human tick).
7. **Report** (Done evidence below).

Apply the Defaults table instead of asking: Decision Log row, open item, continue.
**Stop and ask** only for: missing datasheet; unnamed package/grade/option choice; mirrored, rotated or mismatched
footprint; pin count or position conflict in the DS; missing NC/EP wording; two defaults that conflict; anything unsafe.
(Circuit design follows `ee-design` stop-and-ask.)

## Review: one goal
A person verifies only what a machine cannot. Classes: DERIVED (script re-proves it each verify, no stamp), HUMAN
(read from a PDF table, figure or equation, or used by a calc: one hash-bound tick), REFERENCE (display only).
Agent findings (verifier, adversarial) go to the PR description as applied or open items; nothing from them is committed.
Agents never stamp. Component PRs carry no stamps; the human check is its own `review/*` PR of stamps only
(`docs/spec/review.md`, `docs/spec/review-view.md`, CONTRIBUTING.md).

## Done: evidence to show
1. Pin table (number, name, type, function, cite); symbol match and format version.
2. Land pattern vs pads per dimension, courtyard, pin-1 marker, STEP status.
3. Param counts per kind; equations with cites; EXAMPLES results.
4. Verifier and adversarial findings, applied or logged.
5. Verbatim tails of `lib.check`, `pcb build`, unittest.
6. README Zener checks table; `grep -rn 'waive_[a-z_0-9]*=' --include='*.zen' . | grep -v '/.pcb/'`.
7. Decision Log (default | case | open item); open items (DS ambiguities, 25 C-only and curve values,
   revision/PCN/lifecycle, lead finish, second sources, 3D-model pin-1 check).
8. `.review-cache/<Mfr>/<Value>/DELTA.md` rows listed for the human (key, state, status; `docs/briefs/ds-review.md`).

Modules: `ee-design`, `schematic-style`, `zener-wrapper` section 3. Examples: `docs/spec/lib-api.md`.
